# TIMECORE 自主迭代路线图（2026-09-17 夜间 → 09-18 早 8:00）

> 授权：用户委托 AI 全自主推进（功能 / UI / 动效 / 音效），要求「眼前一亮、有创意」，
> 前提：**不让项目操作变得更复杂**（不加新按钮/新流程，优先零 UI 成本的环境智能）。
> 每定一个方向就在此记录；每完成一个大版本（=一个方向收口）即发版 GitHub。
> 红线不变：绝对时间节点 / 显示不回跳 / 到点必触发 / 辉光配额 / 六组 E2E 保持全绿。

## 选题原则

1. 零操作成本：所有新东西默认自动生效或默认关闭，绝不新增必用按钮。
2. 主题契合：一切围绕「时间装置」——让用户**感觉到时间的流动**，而不是多一个功能。
3. 每个方向独立可发版：做完一个发一个，中断随时安全。
4. 验证纪律：node --check → 相关 E2E → 全量七组套件（cycle19|21|24|26|27|30|31）→ 截图留档。

### 方向 F：星空生动化（v1.3.3）
- 动机：星球背后是空的——一片会呼吸的远景星野 + 偶发流星，让「悬浮在太空」成立。
- 预期：约 320 颗远星（自定义 shader，相位错开的慢闪烁）；流星每 30-90s 一颗，拉伸光斑 0.9s 划过，质量低档不显示；`TC.Scene.meteor()` 强制触发（测试）。

### 发版事故记录（方向 0/E 之间）
- v1.3.0 首跑 CI 在 Build Windows installer 挂死 35 分钟（v1.2.4 同步骡全程 97s）→ 取消 rerun 后 2 分钟成功。
- v1.3.1 连续三次挂死（含镜像 env 后仍挂）。日志揭示真相：**不是死锁，是 GitHub runner 到发布 CDN 的上行极慢**（publish 阶段 3 分钟才 overwrite 一个文件），长等待后其实会完成。
- 治理：release.yml 加 `timeout-minutes: 15` + pwsh 重试 3 次 + npmmirror 双镜像（electron 与 electron-builder-binaries）。此后 tag→CI→PATCH 流程可自愈，无需人工盯守。

## 逐方向记录

> 收官备注（05:40 前）：方向 0-H 全部收口，共 7 个版本（v1.3.0～v1.4.1 + 本次配图刷新）。

### 方向 I：渲染降耗（v1.5.0）——含对 backlog「粒子 InstancedBufferGeometry」的评估结论
- 评估：粒子系统 900 颗 × 30fps 的 CPU 更新实测开销 ~0.05ms，缓冲上传 ~11KB/帧——重写为 InstancedBufferGeometry + 着色器积分的收益接近零，而 kickParticles/respawn 等交互逻辑迁到 GPU 会带来视觉回归风险。**结论：放弃字面方案，做真正的大头**。
- 真正的功耗黑洞：仅时间形态下 #scene 是 display:none，但 WebGL 仍对隐藏 canvas 跑完整管线（实测每帧 42 draw calls / 17136 三角形）——悬浮钟变成隐形电暖器。
- 实现：render() 检测 body.clockmode 直接整帧早退（skipStreak 连续跳帧计数暴露于 debugSun 探针）；退出形态即恢复。cycle31 新增第 8 断言守护。
> 未来候选（按 ROI 排序，未排期）：粒子 InstancedBufferGeometry 降耗、每日击拍统计面板、局域网伴侣页、音效主题包——均见 DESIGN.md §7 backlog。

### 方向 0：钟面动效四件套（v1.3.0）
- 动机：用户反馈悬浮钟面「生硬」；已在循环 #45 完成并验证（回归 70/70 + 探针实证）。
- 内容：数字 tick（变化对 240ms 上浮淡入）、tweenBounds 窗口缓动（形态/滚轮/还原统一，170ms easeOutCubic）、clockIn/panelIn 形态 morph、呼吸边（辉光配额钟面唯一例外）；附带 win:state 推送让右键进出钟面零延迟。
- 结果：全部完成，E2E 全绿，本版本随 v1.3.0 发布。

### 方向 A：行星真实太阳（v1.3.1）
- 动机：TIMECORE 是时间装置，3D 星球却永远被固定方向照亮——让星球昼夜随**真实时间**转，是「眼前一亮」且零操作成本的核心创意。
- 预期：根据本地时间计算太阳直射经度（近似：正午 12:00 照亮朝屏幕一侧），光照方向向量绕星球缓慢旋转；夜间半球压暗 + 微弱冷色，晨昏线柔和过渡；能量环/粒子不受影响。
- 风险：scene3d.js shader 改动需截图验证；性能不回退。

### 方向 B：到点音景（v1.3.2）
- 动机：到点目前是单音白闪+提示音，缺少「仪式感」；释放瞬间应该是这个装置的 signature moment。
- 预期：分层释放音（sub 冲击 + 五声音阶琶音 + 短尾混响感），复用现有 track 音量体系；不新增设置项；倒计时 10s 阶段音与自由节拍音色不动（已验证可闻性）。
- 风险：音频调度走绝对节点预排，改动集中在音色合成层，不碰调度逻辑。

### 方向 C：钟面秒环与零点脉动（v1.3.3）
- 动机：纯数字钟面缺一个「时间的形状」；一圈极细秒弧让 60 秒的循环可见，归零时整窗一次脉动把「到点必触发」变成看得见的仪式。
- 预期：SVG/conic-gradient 秒进度弧（GPU 合成，颜色中性青），归零瞬间钟面整体 1 次柔和 scale/glow 脉动；不改信息结构，不加按钮。
- 风险：钟面只有时分秒.毫秒的信息红线——弧是「秒的可视化」不是新信息，设计上要薄（≤3px）。

### 方向 D：开场仪式（v1.3.4）
- 动机：冷启动瞬间直接整屏闪现，缺少「装置通电」的感觉。
- 预期：窗口启动 300ms 淡入 + 核心能量从 0 充能一次；欢迎卡入场动画。零交互变化。
- 风险：启动耗时不能增加（动画只在渲染层，不阻塞 boot）。

### 方向 E：收口打磨（v1.4.0）
- 动机：一夜迭代的收束——巡检细节、更新 README 与截图、写版本总结。
- 预期：全量回归 + 真机走查清单 + 文档对齐。

## 发版纪律（每版本执行）

1. version bump（package.json）→ commit → tag → push
2. CI 出包 → GitHub API PATCH draft:false（UTF-8 JSON，写清本版内容）
3. 验证 releases/latest 版本号正确
4. 回写本文件状态列 + PROGRESS.md + memory
